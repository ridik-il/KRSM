# Test list: v0.5-slice6-scope-channel  (source: docs/design/v0.5-slice6-scope-channel.md rev 3)

Ordered as vertical slices — implement one before writing the next. Each entry is a
capability observable through a public interface (`scope.Compile`, `contract.Parse`,
`webhook.Server.Handle`, `krsm serve` flag assembly), never a private helper.

Gate for every step: `make check` (gofmt -s, vet, golangci-lint, staticcheck,
`go test -race`, archguard, sourceguard) green before moving on.

## Step 1 — apiVersion flip + contract dimensions (`scope/`, `internal/contract/`)

1. [ ] A TaskContract declaring `apiVersion: krsm.io/v1alpha1` compiles; one declaring
       `krsm.io/v1` is rejected with an unrecognised-apiVersion error.
2. [ ] A contract with an `ownership` allow-clause (`root` carrying Kind + name) compiles
       to exactly the clause `closure.OwnershipClause(root)` produces, so it authorises
       the same tree `scope.Derive` synthesizes.
3. [ ] A contract with a `namespace` allow-clause compiles to a namespace-dimension clause
       covering that namespace.
4. [ ] A structurally invalid ownership clause (clause-level GVK, name, or selector
       alongside `root`) and a namespace clause with no namespace are both rejected —
       `closure.ScopeClause.Validate`'s rules surface through `Compile`.
5. [ ] `dim: reference` is still rejected as an unsupported dimension (the fail-closed
       proof golden 22 asserts, re-pointed from `ownership`).
6. [ ] Goldens 01–27 produce byte-identical verdicts after the flip; golden 22 still fails
       at load with an "unsupported scope dimension" error naming `reference`.
7. [ ] `contract.Parse` accepts golden 21's `matchExpressions` selector clause and an
       `ownership` clause's `root` **under strict decoding**, and rejects an unknown
       `spec.allow[]` field.
8. [ ] `contract.Parse` maps a TaskContract CR's JSON form and the equivalent YAML to
       identical compiled clauses (the informer/loader parity pin).

## Step 2 — `resolveScope` L0 + L1 (`webhook/`)

9.  [ ] A request with no governing annotations resolves to provenance
        `derived:ownership-tree` with clauses equal to `scope.Derive(target)` — the
        existing slice-5 behavior, unchanged.
10. [ ] `krsm.io/target: "<Kind>/<ns>/<name>"` on `oldObject` re-roots the ownership tree
        at that ref, provenance `annotation`, yielding a verdict the request target alone
        could not express.
11. [ ] A group-qualified `krsm.io/target: "<Kind>.<group>/<ns>/<name>"` resolves to that
        group's tracked GVK and re-roots.
12. [ ] An unqualified kind token matching two tracked GroupKinds fails closed
        `scope-unresolved`; the qualified form of the same Kind resolves.
13. [ ] A kind token matching no tracked GVK fails closed `scope-unresolved`.
14. [ ] A malformed `krsm.io/target` (wrong segment count, empty or whitespace segment,
        empty namespace for a namespaced kind) fails closed `invalid`.
15. [ ] An UPDATE that adds `krsm.io/target` only in `object` does **not** self-authorize —
        the annotation is read from `oldObject`, so the request falls to L0.

## Step 2b — group-aware root pre-resolution (`state/`, `webhook/`)

15b.[ ] `Provider.GetByGVK(gvk, ns, name)` returns the object for that exact **GVK**, so two
        tracked kinds sharing a Kind + namespace + name but differing in **group** resolve to
        different objects (the group-blind `byHuman` bucket must not decide it).
15c.[ ] An L1 re-root Ref is stamped with the resolved object's **real UID** before the
        ownership clause is built, so the subtree walk keys on `uid:` — with two colliding
        same-Kind/different-group objects present, the re-root authorizes the subtree of the
        one the annotation's group named, not whichever the index stored last.
15d.[ ] **(corrected)** A re-root naming an object absent from the index fails closed
        `scope-unresolved` in **both** modes. It must NOT stay uid-less: with a
        same-`Kind/ns/name` object present in another group, a uid-less root resolves through
        the group-blind `byHuman` bucket and authorizes *that* object's subtree — an
        `allowed=true` mis-scope, demonstrated in step 2b. Assert the collision fixture
        specifically, not just the empty-index case.

## Step 3 — cross-boundary allowlist (`webhook/`)

16. [ ] An *indirect* escape into an allowlisted namespace is exempted: audit emits no
        warning, enforce admits.
17. [ ] An indirect escape to a cluster-scoped ref whose `{Group, Kind}` is allowlisted is
        exempted; the same Kind in a different group is **not**.
18. [ ] A direct DELETE/UPDATE whose *target* sits in an allowlisted namespace still
        Warns/Blocks — the allowlist never exempts the action target.
19. [ ] A non-allowlisted escape alongside an allowlisted one still Warns/Blocks; when
        every indirect escape is exempted the verdict flips Block → Allow.
20. [ ] A fail-closed Block with an empty `Escaping` set is never softened by the
        allowlist.
21. [ ] A contract-provenance (L3) decision ignores the allowlist entirely.

## Step 4 — L3 contract resolution (`webhook/`)

21b.[ ] An L3 contract's `dim: ownership` Root written **without a namespace** defaults to
        the TaskContract CR's own namespace (not `"default"`), so it walks the intended
        subtree; see the design's "Ownership-root identity" addendum.
22. [ ] `krsm.io/scope: "<ns>/<name>"` on `oldObject` resolves the TaskContract by live
        GET; a contract authorising the collateral **Allows** an action derived-enforce
        would Block, with provenance `contract`.
23. [ ] Each unresolvable case fails closed `scope-unresolved` in **both** modes: nil
        getter, contract not found, GET error, RBAC-forbidden, expired deadline,
        uncompilable contract, unknown-field CR.
24. [ ] A cross-namespace `krsm.io/scope` reference fails closed `scope-unresolved`, as
        does a `krsm.io/scope` on a cluster-scoped request.
25. [ ] A malformed `krsm.io/scope` (not exactly two non-empty segments) fails closed
        `invalid`.
26. [ ] While L3 is unavailable (getter erroring), L0 and L1 requests on the same server
        still resolve and decide normally.
27. [ ] With both `krsm.io/scope` and `krsm.io/target` set, the contract wins.
27b.[ ] `filterEscapes` reports which refs it exempted, so entry 28's
        `krsm.io/allowlist-exempted` can name them — its step-3 signature
        `(dec, target) closure.Decision` returns no list, so widen it to
        `(closure.Decision, []closure.Ref)` rather than recomputing the diff in `Handle`.
28. [ ] `AuditAnnotations["krsm.io/scope-provenance"]` is set on every decided response;
        `krsm.io/allowlist-exempted` appears **only** when an exemption occurred and lists
        the exempted refs.

## Step 5 — serve wiring (`cmd/krsm/`)

29. [ ] `--allow-namespace a,b` and `--allow-cluster-scoped-kind Node,Foo.example.com`
        build the `Allowlist` with GroupKind keys (bare Kind ⇒ core group), trimming
        whitespace and dropping empties.
30. [ ] `buildWebhookConfig` carries the injected `contractGetter`, the allowlist, and the
        annotation keys onto `webhook.Config` — the dropped-field regression guard.
31. [ ] `--scope-annotation` / `--target-annotation` override the defaults end-to-end
        through `resolveScope`.
