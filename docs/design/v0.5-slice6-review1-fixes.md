# Design: v0.5-slice6-review1-fixes
Status: implemented (design-check-tdd: 2 drifts corrected) · Date: 2026-10-12 · Slug: `v0.5-slice6-review1-fixes` · Plan: docs/plans/v0.5-slice6-review1-fixes.md

## Summary
This closes the round-1 review of PR #41 on the slice-6 branch. There are two
behavioural fixes:
- A live TaskContract's resource/selector clauses inherit the contract's namespace,
  instead of the loader's `default`.
- The L1 re-root is bounded to the action target or an in-namespace owner ancestor of it.

There are two serve-side hardenings: fail-fast key and allowlist validation, and a
re-key warning. The rest is documentation. Two widening paths are deliberately kept as
documented residuals: a contract's grant is not bounded by its namespace, and an agent
can annotate in one request and use that annotation in the next. No `closure/` change
is made, and every golden verdict is unchanged.

## Interfaces / contracts

### `internal/contract`
- `ParseCR(raw) (scope.TaskContract, error)` and `Parse(raw)` keep their signatures.
- **Behaviour change in the shared clause builder.** For `dim` `""`/`resource`/`selector`,
  an empty clause `namespace` resolves to the contract's `metadata.namespace` when that is
  non-empty. Otherwise it resolves to `default`, the offline loader convention, kept for
  YAML contracts without a namespace. Cluster-scoped kinds still resolve to `""`. The
  `namespace` and `ownership` dims are unchanged: they pass through literally.
- Internally, `clauseNamespace(rc rawAllowClause, contractNamespace string) string` mirrors
  `rootNamespace`. It is unexported; no test calls it directly.

### `webhook` — L1 resolution (`resolveScope` → `resolveTargetRoot`)
- L1 succeeds only if the re-root R satisfies both conditions below. A miss on either is
  `reasonScopeUnresolved` in both modes; it is never a fall-back to L0.
  1. **Same namespace:** `R.Namespace == target.Namespace`. A namespaced target can only
     re-root to a namespaced R in its own namespace, and a cluster-scoped target to a
     cluster-scoped R.
  2. **Ancestor or self:** R is the target (equal real uid), or the target's uid is
     reachable from R by breadth-first `State.OwnedChildren`. The walk runs over uid-pinned
     refs with a visited set, so it terminates on cycles.
- The target's identity for (2) is its real uid. If the request target carries no uid, it
  is resolved with `GetByGVK(target.GVK, ns, name)`; a miss is `scope-unresolved`.
- Error text names the rule broken. Examples:
  - `krsm.io/target "Deployment/other/web": re-root must be in the target's namespace "prod"`
  - `... re-root Deployment.apps/prod/web is not an owner of the target`
- Everything else is unchanged: syntax (`invalid`), kind resolution, and real-uid pinning.

### `webhook.Config` / `webhook.New`
- The `TargetAnnotation`/`ScopeAnnotation` doc comment changes. Re-keying makes the old
  key **inert**, so an object annotated with it falls to **L0**, and L0 may be wider *or*
  narrower than what the old key named. It is not described as "the safe direction".
- `New` keeps its collision check (library callers). The serve CLI checks earlier.

### `cmd/krsm serve`
In the existing fail-fast block of `runServe` (next to `agentMatcher`/`parseAllowlist`),
before `serveWebhook` makes any cluster contact, `runServe` rejects these, each with an error
naming the flag and the value:
- **Empty keys:** `--target-annotation ""` or `--scope-annotation ""`.
- **Malformed keys:** a key that is not a valid annotation key, `[<dns-subdomain>/]<name>`
  per the k8s qualified-name rules, checked with
  `k8s.io/apimachinery/pkg/util/validation.IsQualifiedName`. The apimachinery module is
  already required, so this adds no new module dependency.
- **Colliding keys:** any two of {target, scope, agent annotation} that are equal. The
  agent annotation counts only when non-empty, because `""` legitimately disables
  annotation matching.
- **Allowlist entries:** an empty entry (`a,,b` or a trailing comma) or `*` in
  `--allow-namespace` / `--allow-cluster-scoped-kind`.

Other serve changes:
- **Re-key warning:** when a key differs from its default, one startup line is printed
  through the serve logger, naming the old key, the new key, and that objects annotated
  with the old key fall to L0.
- **Dead code:** `buildWebhookConfig` assigns `Contracts` unconditionally, and the
  typed-nil comment goes. A nil `*DynamicContractGetter` is never passed, because
  `runServe` always constructs one.

## Data model
No type changes.

## Behavior
| Request | Before | After |
|---|---|---|
| L3 contract `prod/c`, clause `{ConfigMap, name: "*"}` with no namespace | grants `default/*` ConfigMaps | grants `prod/*` ConfigMaps |
| L1 re-root at the target's owner Deployment (same ns) | re-roots | re-roots (unchanged) |
| L1 re-root at the target itself | re-roots (= L0 tree) | unchanged |
| L1 re-root at an unrelated same-namespace object | re-roots; the target then escapes (Warn in audit) | **deny `scope-unresolved`**, both modes |
| L1 re-root at a cluster-scoped owner of a namespaced target | re-roots; the scope spans every namespace the owner reaches | **deny `scope-unresolved`** |
| L1 re-root in another namespace | re-roots; the target escapes | **deny `scope-unresolved`** |
| L1 owner chain broken (an intermediate owner not tracked) | re-roots | **deny `scope-unresolved`** (the error names the rule) |
| `serve --scope-annotation ""` | silently uses the default | rejected at startup |
| `serve --allow-namespace '*'` | literal `*`, which matches nothing | rejected at startup |
| An empty-`allow` contract, enforce mode | deny-all (Compile accepts it) | unchanged, now pinned by a test; comment corrected |

## Alternatives considered
**For the L1 bound:**
- *Same-namespace only, no ancestor check.* Closes the cross-namespace widening, but a
  non-ancestor re-root would still be "caught" only by the target escaping, which audit
  softens to a Warn. Rejected in favour of an explicit, named deny.
- *A depth limit on the ancestor walk.* Arbitrary, and it doesn't express intent.
- *Walking up through `Owners`.* `closure.OwnerRef` has no group, so an upward walk
  re-enters the group-blind lookup that slice 6 removed. Walking down from the uid-pinned R
  uses `OwnedChildren`, which is keyed by owner uid. Rejected.

**For the findings kept as residuals:**
- *Bounding contract grants to the contract's namespace (finding 2).* Rejected for now.
  Cross-namespace and cluster-scoped grants are legitimate for operator-authored
  contracts, and the real control is who may author them. Slice 7 RBAC must give agents
  no write on `taskcontracts`; `SECURITY.md` states this as a requirement.
- *Denying agent UPDATEs that change a governing annotation (finding 4).* Deferred. It
  needs an old/new diff on every agent UPDATE and touches the matcher path. With the L1
  bound in place, the two-step only reaches the target's own owner tree, which is the
  documented L1 use. It is recorded alongside #42.

## Trade-offs & risks
- The L1 bound costs one `OwnedChildren` walk, bounded by R's subtree, on L1 requests only.
- An owner chain that passes through an untracked kind is now denied rather than
  approximated. This fails closed, and the message names the rule.

## Testability
Every behaviour is observed through `Server.Handle` (verdict, reason code, and audit
annotations), `contract.ParseCR`/`scope.Compile`, or `runServe`'s returned error and
logged output. See `v0.5-slice6-review1-fixes-tests.md`.
