- **D1 — `scope.Compile` cannot compile an ownership clause.** The plan assumed the

  `Root`, and `reference` is not a dimension at all (`closure/model.go:127-130` defines
  exactly four). **Decision: extend the compiler now** — add `AllowClause.Root`, accept
  `DimOwnership` + `DimNamespace`. This closes a v0.4 gap (closure implements both dims;
  only the *contract surface* lagged) and is a prerequisite for v0.6's `ownership-tree`
  template. **Cost, accepted:** golden `22-taskcontract-fail-closed` exists to assert
  `dim: ownership` is rejected, so it is re-pointed at `dim: reference` (genuinely never
  implemented) with its comment and expected `loadError` updated. The DoD's "only the
  `apiVersion` literal changes" is amended accordingly — golden 22's *verdict class*
  (a load-time fail-closed error) is unchanged; only the dimension it names and the
  error text change.
- **D2 — nothing resolves a Kind string to a GVK.** `clusterInfo` offers `Namespaced`,
  `KindFor(group, **resource**)` (GVR→GVK, plural — not a Kind) and `Tracked(gvk) bool`;
  none resolves a Kind and none enumerates the tracked set to detect ambiguity.
  **Decision: add `GVKsForKind(kind string) []closure.GVK`** to `state.Provider` (over the
  same `p.targets` map `Tracked` already walks) and to the `clusterInfo` interface, and
  accept **`<Kind>[.<group>]`** in `krsm.io/target` — the grammar the CLI and
  `--allow-cluster-scoped-kind` already use. A bare Kind matching ≥2 GroupKinds fails
  closed `scope-unresolved`; a group-qualified Kind is always unambiguous.
- **T3 — strict parsing would reject the existing selector golden.** `rawAllowClause`
  (`internal/scenario/scenario.go:645`) declares only `dim/gvk/namespace/name`; the
  selector is read out-of-band by `scopeSelectorFrom`. Under `DisallowUnknownFields`
  golden 21's `matchExpressions` becomes an unknown field. The extracted
  `contract.Parse` must declare `matchLabels`/`matchExpressions` (and now `root`) as
  real fields on the raw clause.
- **T4 — `buildWebhookConfig` is deliberately pure** (`cmd/krsm/main.go:694`, hermetic per
  PR #36 finding 9). The `contractGetter` needs a live dynamic client, so it arrives as a
  **parameter** (`buildWebhookConfig(o, mode, provider, contracts contractGetter)`), never
  constructed inside. `serveWebhook` has `cfg *rest.Config` in scope to build it.
- **T5 — no source-guard conflict.** `webhook/sourceguard_test.go` blocks mutating client
  verbs only; the L3 live `.Get(` is permitted.

## Summary
Replace the single `scope.Derive(action.Target)` call in `webhook/server.go` `Handle`
with a **`resolveScope`** seam selecting the scope provenance per request —
**L3 contract > L1 `krsm.io/target` annotation > L0 derived** — returning a
`scope.ScopePredicate` the unchanged `closure.Safe` consumes. Three security semantics
drive rev 2 (from design review):
1. **The allowlist can never exempt the admission-request target** — only *indirectly
   reached* cross-boundary resources are eligible, and cluster-scoped exemptions are keyed
   by **GroupKind**, not Kind.
2. **Contract/target references are bearer capabilities** — chosen explicitly, bounded by
   a **same-namespace** constraint and read from **`oldObject` only** (a request cannot
   self-authorize), with identity/UID/expiry binding deferred to a tracked follow-up.
3. **Contract resolution is fail-closed** — L3 does a **deadline-bounded live GET** of the
   `TaskContract` (authoritative — no informer revocation-staleness window); any
   failure/absence fails closed, and L3 unavailability never disables L0/L1.

Plus: the `TaskContract` `apiVersion` flip `krsm.io/v1` → `krsm.io/v1alpha1` in
`scope.Compile` + tests + contract goldens (verdicts identical); the CRD manifest / RBAC /
samples that *declare* `v1alpha1` are **slice 7**. No engine, `closure.Safe`, or new scope
dimension change.

## Security model & trust (rev 2 — the core of the review)

### Capability model (explicit choice)
For v0.5, `krsm.io/scope` (contract reference) and `krsm.io/target` (L1 re-root) are
**bearer capabilities**, with these guardrails, and identity binding deferred:
- **Same-namespace only.** A `krsm.io/scope: "<ns>/<name>"` reference is honored **only
  when `<ns>` equals the request target's namespace**; a cross-namespace reference **fails
  closed** (`scope-unresolved`). This bounds "grab another namespace's permissive
  contract" to the namespace the agent already acts in (where RBAC already gates it). A
  **cluster-scoped request** (no namespace) may not use L3 in this slice → `scope-unresolved`.
- **Read from `oldObject` only** (below) — a request cannot mint its own authorization.
- **Accepted, documented residual:** within one namespace, a compromised agent can still
  reference any TaskContract in that namespace or re-root L1 anywhere. Binding a contract
  to the requester's ServiceAccount/task identity (UID + expiry) is the correct fix; it is
  **ADR-0003's deferred trust question** and is filed as a follow-up issue (v0.6 /
  threat-model). The audit-first default and fail-closed resolution bound the blast radius
  meanwhile. This is stated in the ADR/SECURITY docs, not hidden.

### Annotation source — no self-authorization
Scope-governing annotations (`krsm.io/scope`, `krsm.io/target`) are read **only from the
request's `oldObject`** — the object as it existed *before* this action:
- **DELETE / UPDATE** → `oldObject`. An UPDATE that *adds* `krsm.io/scope` in the same
  request **does not** authorize that request (the annotation isn't in `oldObject`).
- **CREATE** and **sub-resources without an `oldObject`** (eviction) → no `oldObject`
  annotations → **L0 derived** (CREATE is admitted pre-closure anyway).
This differs deliberately from the *identity* matcher (slice 5, reads object-or-oldObject):
identity answers "is this an agent?", authorization must be pre-existing.

### The allowlist never exempts the action target
`filterEscapes(dec, target, prov)` (rev 2 signature) exempts an escaping ref **iff all**:
its key ≠ the action target's key (never the target itself), it was reached *indirectly*
(any member of `Escaping` that is not the target), and it is either in an allowlisted
namespace **or** a cluster-scoped ref (`Namespace == ""`) whose **`{Group, Kind}`** is
allowlisted. Direct mutation/deletion of an allowlisted `Namespace`/`Node`/CRD is therefore
still Warned/Blocked. Cluster-scoped exemptions are keyed by GroupKind to avoid CRD Kind
collisions. Applied for **L0/L1 provenance only**; L3 ignores it; a fail-closed Block
(empty `Escaping`) is never touched.

## Interfaces / contracts

### `scope/` (stdlib-only, archguard)
```go
const ProvenanceAnnotation Provenance = "annotation" // L1 re-root (beside contract, derived:ownership-tree)
// scope.Compile: wantAPIVersion = "krsm.io/v1alpha1"  // flip; also accept nothing else

// rev 3 (D1): the contract surface gains the two dimensions closure already implements.
type AllowClause struct {
    Dim       closure.ScopeDim // "resource" | "selector" | "namespace" | "ownership"
    GVK       closure.GVK
    Namespace string
    Name      string                // Dim == resource
    Selector  closure.LabelSelector // Dim == selector
    Root      closure.Ref           // Dim == ownership — identity lives on Root
}
// compileClause accepts DimOwnership and DimNamespace; closure.ScopeClause.Validate
// (closure/model.go:216) already enforces their structural rules (ownership: Root with a
// Kind+Name, no clause-level GVK/namespace/name/selector; namespace: non-empty Namespace,
// no name/selector/Root), so the compiler adds the dim cases and passes Root through —
// no new validation logic and no closure change.
```

### `internal/contract/` (new shared package — one parse path, structurally strict)
```go
package contract
// Parse maps the TaskContract wire form (JSON or YAML bytes) to a scope.TaskContract.
// It is STRUCTURALLY STRICT: unknown fields are rejected (json.Decoder.DisallowUnknownFields
// over the JSON form), because scope.Compile cannot reject fields a lax parser already
// discarded and the CR is attacker-influenced. It resolves selectors and defaults
// namespaces; it does NOT semantically validate — scope.Compile is the fail-closed authority.
func Parse(raw []byte) (scope.TaskContract, error)
```
`internal/scenario.parseTaskContract` becomes `contract.Parse` (selector/namespace helpers
move with it). (Note: JSON is a subset of YAML 1.2 — a YAML parser accepts the JSON we
marshal from `unstructured`; the earlier draft stated this backwards.)

**Rev 3 (T3):** strictness forces the raw clause struct to declare every field the wire
form carries — today `rawAllowClause` omits the selector keys (read out-of-band by
`scopeSelectorFrom`), so `DisallowUnknownFields` would reject golden 21's
`matchExpressions`. The moved struct therefore becomes:
```go
type rawAllowClause struct {
    Dim              string          `json:"dim"`
    GVK              rawRef          `json:"gvk"`
    Namespace        string          `json:"namespace"`
    Name             string          `json:"name"`
    MatchLabels      map[string]string `json:"matchLabels"`      // Dim == selector
    MatchExpressions []rawMatchExpr    `json:"matchExpressions"` // Dim == selector
    Root             *rawRef           `json:"root"`             // Dim == ownership (D1)
}
```

### `webhook/scope.go` (new)
```go
// contractGetter resolves a TaskContract by an AUTHORITATIVE live read (not a cache):
// a stale contract is a false-ALLOW (the C2 class), so L3 reads through. Deadline comes
// from the request ctx. Returns ErrContractNotFound for absent CRD or missing CR.
type contractGetter interface {
    Get(ctx context.Context, namespace, name string) (*unstructured.Unstructured, error)
}
var ErrContractNotFound = errors.New("taskcontract not found")

// Allowlist: cross-boundary escape hatch for DERIVED (L0/L1) modes. ClusterScopedGroupKinds
// is keyed by {Group, Kind}; Namespaces by namespace. Never exempts the action target.
type Allowlist struct {
    Namespaces             map[string]bool
    ClusterScopedGroupKinds map[closure.GVK]bool // Group+Kind (Version zeroed)
}
func (a Allowlist) filterEscapes(dec closure.Decision, target closure.Ref) closure.Decision

// resolveScope: L3 (krsm.io/scope) > L1 (krsm.io/target) > L0. Reads the governing
// annotations from oldU (oldObject) only. Returns the predicate + a fail-closed reason on
// error (reasonInvalid for malformed syntax, reasonScopeUnresolved for a well-formed
// reference that cannot be resolved: not-found, cross-namespace, ambiguous L1 Kind,
// uncompilable, or a live-GET/RBAC/deadline failure).
func (s *Server) resolveScope(ctx context.Context, req *admissionv1.AdmissionRequest,
    oldU *unstructured.Unstructured, target closure.Ref) (scope.ScopePredicate, reasonCode, error)
```
Annotation key consts: `krsm.io/target`, `krsm.io/scope`.

### `webhook/server.go` — `Config`, taxonomy, `Handle`, structured provenance
```go
type Config struct {
    // ... existing ...
    Contracts contractGetter // nil → L3 disabled: a krsm.io/scope reference fails closed
    Allowlist Allowlist
    // rev 3 addendum (step-2 finding 3): the annotation keys are configurable, so they
    // belong on Config rather than as package consts — test-list entry 31 requires
    // --target-annotation/--scope-annotation to reach resolveScope. Empty → the defaults
    // krsm.io/target and krsm.io/scope.
    TargetAnnotation string
    ScopeAnnotation  string
}

// rev 3 (D2): clusterInfo (webhook/action.go:25) gains the Kind resolver L1 needs.
// KindFor is GVR→GVK (plural resource) and cannot answer this; Tracked is a yes/no over a
// known GVK and cannot enumerate. *state.Provider implements it over the same p.targets
// map Tracked already walks.
type clusterInfo interface {
    cluster.ScopeInfo
    KindFor(group, resource string) (closure.GVK, bool)
    Tracked(gvk closure.GVK) bool

}

```
`Handle` (rev 2): `pred, rc, err := s.resolveScope(ctx, req, oldU, action.Target)` → on
err, `deny(rc, …)`; `dec := closure.Safe(...)`; if `pred.Provenance` ∈ {derived, annotation}
`dec = s.allowlist.filterEscapes(dec, action.Target)`; `dec = mode.Apply(dec)`;
`resp := decisionResponse(dec, pred.Provenance)`; **also set structured audit metadata**:
```go
resp.AuditAnnotations = map[string]string{"krsm.io/scope-provenance": string(pred.Provenance)}
// when the allowlist exempted refs, additionally:
resp.AuditAnnotations["krsm.io/allowlist-exempted"] = closure.JoinRefs(exempted)
```
so provenance and exemption are machine-readable in the API-server audit log, not only in
`status.message`/`warnings[]`.

## Behavior

### Annotation parsing (strict — reason mapping)
- Read from `oldU`; absent `oldU` → L0.
- `krsm.io/target`: split on `/`, **exactly 3 segments**; segment 0 (the kind token) and 2
  (Name) non-empty and whitespace-free; segment 1 (namespace) may be empty **only** for a
  cluster-scoped kind. Any other shape (wrong count, empty/space segments) → `invalid`.
  **Mirror rule (step 2, implemented):** a **non-empty namespace on a cluster-scoped kind**
  (`PersistentVolume/prod/pv-1`) is likewise `invalid` — a malformed shape, not a tolerated
  one, consistent with this section's strictness.
  **Rev 3 (D2):** segment 0 is `<Kind>[.<group>]` — the same token grammar the CLI's
  `ResolveKind` and `--allow-cluster-scoped-kind` use (a bare Kind means the core group
  only when qualified with a trailing dot; unqualified means "any group, must be unique").
  Resolution goes through the new `clusterInfo.GVKsForKind(kind)`:
  - group-qualified → the one tracked GVK with that Group+Kind, else `scope-unresolved`;
  - unqualified, exactly one tracked GroupKind → that GVK;
  - unqualified, **≥2 tracked GroupKinds → `scope-unresolved`** (S2 ambiguity — never
    choose arbitrarily; the author qualifies the token to disambiguate);
  - zero matches → `scope-unresolved`.
  A unique match re-roots `scope.Derive(reRootRef)` with provenance `annotation`.
- `krsm.io/scope`: split on `/`, **exactly 2 non-empty segments** `<ns>/<name>` → else
  `invalid`. `<ns>` must equal the request target namespace → else `scope-unresolved`
  (cross-namespace). Cluster-scoped request + `krsm.io/scope` → `scope-unresolved`.

### Ownership-root identity (rev 3 addendum — resolved during step 1)
Both L1's re-root Ref and an L3 contract's `dim: ownership` Root arrive **without the API
server's `metadata.uid`**, while live closure members carry real uids. This resolves
correctly and needs no new machinery: `state/index.go:194` `lookupLocked` tries the uid
and then **falls back to `byHuman[Ref.String()]`** (the `Kind/ns/name` form, uid-independent),
and `closure/safe.go:119-121` `ownedSubtree` then normalizes the clause Root to the
canonical uid-bearing Ref before the BFS. A uid-less *or* synthetic-uid root therefore
walks the real subtree.
- **L1:** build the re-root Ref uid-less, then **pre-resolve it** (below).

**Group-blind human key (found during step 2; decided 2026-08-01).** The human fallback is
uid-independent but also **group**-independent: `Ref.human()` (`closure/model.go:47`) renders
only `Kind/ns/name`, and `state/index.go:51,94` keys `byHuman` by that string and
**overwrites on collision**. So `Widget.a.example.com/prod/w` and `Widget.b.example.com/prod/w`
resolve to distinct GVKs in the kind-token parser but hit the *same* index bucket — the root
can resolve to the wrong object and the re-rooted tree then authorizes the wrong subtree
(a mis-scope in the **unsafe** direction, not a fail-closed one). This is **pre-existing
since v0.4**: `cmd/krsm/main.go:460` builds the CLI's live target Ref with neither UID nor
Group. **Decision: fix it in slice 6 for the L1/L3 root path** —
```go
// state.Provider (+ the clusterInfo interface): group-aware, exact.
func (p *Provider) GetByGVK(gvk closure.GVK, namespace, name string) (closure.Object, bool)
```
`resolveScope` stamps the resolved object's **real UID** onto the re-root Ref before building
the ownership clause, so `ownedSubtree` keys on `uid:` and never consults the ambiguous
bucket.

**Correction (step 2b, empirically disproved — this addendum was wrong).** An earlier
revision of this paragraph claimed a `GetByGVK` **miss** could safely leave the Ref uid-less
because "the BFS starts from a nonexistent root and authorizes only the root itself — a
fail-closed Block". **That is false in exactly the collision case this fix exists for.** A
uid-less Ref still goes through the group-blind fallback (`state/index.go` `lookupLocked`
tries `byUID`, then `byHuman[Kind/ns/name]`), and `closure/safe.go` `ownedSubtree` then
normalizes `start` to whatever that bucket holds. Demonstrated: with only
`Widget.b.example.com/prod/w` present and owning the subtree, an annotation naming the
**absent** `Widget.a.example.com/prod/w` returned **`allowed=true`** — the absent a-group root
authorized the b-group Widget's entire subtree. A mis-scope in the unsafe direction, i.e.
the very bug this step was written to close, one level down. Synthesizing a uid does not
help either: `lookupLocked` falls through to `byHuman` whenever the uid misses.

**Corrected rule:** a `GetByGVK` **miss is `reasonScopeUnresolved`** — the annotation names a
root KRSM cannot resolve, which is precisely what that taxonomy code means ("a well-formed
reference that cannot be resolved"). Never a uid-less Ref, never a synthesized uid. This is
the only construction that delivers the stated intent — *a fail-closed deny, never a wider
tree* — and it applies identically to an L3 `dim: ownership` Root in step 4.
The CLI's own uid-less target Ref is filed as a separate follow-up issue, not fixed here.
- **L3:** `internal/contract.SyntheticUID` is an *offline corpus* convention (no API server
  to mint uids); it is harmless live only because of the human fallback above. The
  load-bearing constraint is the **namespace**, not the uid: `NamespaceFor` defaults an
  omitted namespace to `"default"`, so an ownership Root written without a namespace in a
  CR living in `prod` builds the human key `Kind/default/name`, misses, and BFSes from a
  nonexistent root — authorizing only the root itself. That is a **fail-closed Block**, not
  a false ALLOW, but it is a confusing one. **Step 4 must default an ownership Root's
  namespace to the TaskContract CR's own namespace** (which the same-namespace rule already
  pins to the request target's namespace) and test it.

### L3 resolution (fail-closed, authoritative)
`Contracts.Get(ctx, ns, name)` — live GET, bounded by the request ctx deadline:
- `nil` getter, `ErrContractNotFound`, ctx deadline/cancel, RBAC forbidden, any GET error,
  unmarshal/`contract.Parse` failure, or `scope.Compile` error → **deny `scope-unresolved`**,
  both modes. (A stale/deleted/tightened contract cannot leak through — there is no cache.)
- success → `scope.Compile(tc)` → predicate, provenance `contract`.

### Consistency / availability (rev 2 — answering "fully fail-closed")
- **No L3 sync gate needed** — L3 never reads a cache; the live GET is authoritative.
- **L0/L1 stay available while L3 is unavailable** — a GET/RBAC/CRD failure fails *the L3
  request only*; requests without `krsm.io/scope` are unaffected (no shared dependency).
- **Revocation window: none** — a live GET reflects the current contract; a deleted or
  tightened contract takes effect on the next request.
- **CRD installed after startup** — the live GET finds it; **no restart**.
- The existing informer sync gate (slice 5) still governs the **closure state** (`Safe`);
  that is orthogonal to contract resolution.

### Allowlist, mode, provenance
`filterEscapes` (L0/L1) drops only *indirect* allowlisted escapes, never the target; if the
residual escape set empties, Block→Allow; a fail-closed empty-Escaping Block is untouched.
Then `mode.Apply` (audit downgrade of the *residual* computed escape). Provenance +
exemption are reported both in the message and in `AuditAnnotations`.

Unchanged invariants: no model/LLM; validating-only; fail-closed on uncertainty; audit
softens only a computed escape; `closure`/`scope` stdlib-only.

## Alternatives considered
- **Live GET vs informer cache for the contract** — **live GET** (rev 2): an informer
  cache introduces a revocation-staleness window in which a *deleted or tightened* contract
  still authorizes — a security false-ALLOW (the C2 class). L3 is opt-in and rare, so one
  bounded synchronous read is an acceptable cost for authoritative authorization; it also
  removes the L3 sync gate and the CRD-post-startup restart. (Supersedes ADR-0003's
  "resolved from an informer" for the *security* rationale; the closure *state* still uses
  informers.)
- **Allowlist filter target-blind vs target-aware** — target-aware: a target-blind filter
  is a direct authorization bypass (delete an allowlisted Namespace → exempted → Allow).
- **Cluster-scoped exemption by Kind vs GroupKind** — GroupKind: Kind-only collides across
  CRD groups (the S2 class again).
- **Bearer capability vs identity-bound contracts** — bearer for v0.5, *explicitly*, with a
  same-namespace bound + oldObject source + a filed follow-up for identity/UID/expiry
  binding; full binding is out of scope but named, not hidden.
- **Scope annotations from object-or-oldObject vs oldObject-only** — oldObject-only:
  otherwise an UPDATE self-authorizes by adding the annotation in the same request.
- **Strict vs lax `contract.Parse`** — strict (DisallowUnknownFields): `scope.Compile`
  can't reject fields a lax parser silently dropped, and the CR is attacker-influenced.
- **Dedicated `scope-unresolved` vs reuse `invalid`** — dedicated: distinguishes a
  well-formed-but-unresolvable reference (CRD/RBAC/typo/cross-ns/ambiguous) from malformed
  syntax; greppable operational signal.
- **Allowlist post-Safe filter vs a namespace allow-clause** — post-filter: an allow-clause
  would widen `scope(T)` and re-admit unrelated collateral.

## Trade-offs & risks
- **Live GET adds a synchronous read on the L3 path** — bounded by the request deadline,
  fail-closed on timeout; acceptable for the rare, correctness-critical power-user path.
- **Parser extraction touches `internal/scenario`** — covered by golden/loader tests; the
  move must keep them green.
- **Bearer residual within a namespace** — documented + follow-up issue; audit default +
  fail-closed + same-namespace bound limit it.
- **apiVersion flip is a coordinated corpus change** — only the literal changes; parity
  guards identical verdicts. The CRD/RBAC/sample surface is explicitly slice 7.
- **`AuditAnnotations` size** — provenance + a bounded exempted-ref list only; no data.

## Testability
1. L0: no governing annotations → `derived:ownership-tree`; clauses == `scope.Derive`.
2. L1: `krsm.io/target` on `oldObject` re-roots the tree; provenance `annotation`;
   malformed value → `invalid`; **ambiguous Kind (two GroupKinds) → `scope-unresolved`**.
3. L3 happy: same-namespace contract authorising the tree **Allows** an action
   derived-enforce would Block; provenance `contract`.
4. L3 fail-closed: missing CR, nil getter, GET error/RBAC-forbidden, deadline, uncompilable,
   unknown-field CR, **cross-namespace reference**, cluster-scoped request → `scope-unresolved`,
   both modes; **and L0/L1 requests in the same server still succeed** (no shared failure).
5. Priority: `krsm.io/scope` + `krsm.io/target` both set → contract wins.
6. **Allowlist target-safety (new):** direct DELETE/UPDATE of a target *in* an allowlisted
   namespace stays Warn/Block; direct action on a target of an allowlisted cluster-scoped
   **GroupKind** stays Warn/Block; only an *indirect* shared-resource escape is exempted;
   all-indirect-escapes-allowlisted flips to Allow; a fail-closed empty-Escaping Block is
   never softened; L3 ignores the allowlist.
7. **Annotation source (new):** DELETE reads `krsm.io/scope` from `oldObject`; an UPDATE
   that adds the annotation only in `object` does **not** self-authorize (falls to L0).
8. `contract.Parse` golden: a CR (as JSON) and equivalent YAML compile to identical clauses;
   an unknown spec field is **rejected**.
9. apiVersion: `Compile` accepts `krsm.io/v1alpha1`, rejects `krsm.io/v1`; goldens 01–27
   verdicts unchanged.
10. **Structured provenance (new):** `response.AuditAnnotations["krsm.io/scope-provenance"]`
    is set per level; `krsm.io/allowlist-exempted` is set (and lists the refs) only when an
    exemption occurred.
11. serve flags: `--allow-namespace a,b` and `--allow-cluster-scoped-kind Node,Foo.example.com`
    build the `Allowlist` (GroupKind-keyed); L3 wired to a live-GET `contractGetter`
    **passed as a parameter** to `buildWebhookConfig` and carried onto `webhook.Config`.
12. **rev 3 (D1):** `Compile` accepts an `ownership` clause (`Root` with Kind+Name) and a
    `namespace` clause, producing exactly the clauses `closure.OwnershipClause` /
    the namespace dim yield; a structurally invalid one (ownership with a clause-level
    GVK/name/selector, namespace with no namespace) is rejected by `ScopeClause.Validate`;
    `dim: reference` is still rejected as unsupported. Golden 22 (re-pointed) still fails
    closed at load with an "unsupported scope dimension" error.
13. **rev 3 (D2):** `GVKsForKind` returns every tracked GVK with that Kind; an unqualified
    `krsm.io/target` Kind matching two tracked GroupKinds → `scope-unresolved`; the
    group-qualified form of the same Kind resolves and re-roots.
14. **rev 3 (T3):** `contract.Parse` accepts golden 21's `matchExpressions` selector clause
    **under strict decoding** (the regression this trap would have caused) and an
    `ownership` clause's `root`; an unknown spec field is still rejected.

Surfaced during `design-check-tdd` (2026-08-01): `scope.Derive(action.Target)` has **two**
call sites, not one — `webhook/server.go:198` (the seam this slice replaces) and
`cmd/krsm/main.go:326` (the **live** `krsm check` path, `checkLive`). The live-CLI path is
**out of scope** for slice 6 and stays L0-derived, as its comment already states: it has no
`AdmissionRequest`, no `oldObject` to read governing annotations from, and no dynamic

contract channel (a `taskcontract.yaml`/`scope.yaml` in the scenario dir → `scope.Compile`)
and is likewise untouched — except for the `apiVersion` flip in step 1, which its goldens
share. Extending the live CLI to L1/L3 is a possible v0.6 convenience, not a slice-6 goal.
