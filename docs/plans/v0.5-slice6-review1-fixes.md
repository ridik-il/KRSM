## Problem
PR #41 (slice 6, progressive scope channel, branch `24-slice6-scope-channel`) has all six

The round-1 review (2026-10-12) ran three streams: a plan/design completeness audit

Every resolution failure fails closed, but the review found one bug, three scope-widening
paths, and an unfinished step 6. Findings, numbered as in the review record:

1. **A live contract defaults a clause namespace to `default` (bug, verified).**
   `internal/contract/contract.go` `clauseNamespace` → `NamespaceFor` maps an empty
   resource/selector clause namespace to `"default"`, while `rootNamespace` inherits the
   contract's own namespace. CR `prod/task-1` with `{kind: ConfigMap, name: "*"}` grants
   every ConfigMap in `default`, a namespace nobody named, and none in `prod`.
2. **A contract's grant is not bounded by its namespace.** The same-namespace rule bounds
   *where the contract lives*, not *what it grants*: a contract in `prod` can carry
   `{dim: namespace, namespace: kube-system}` or a cluster-scoped ownership root. Safe only
   while agents cannot write `taskcontracts` (slice 7 RBAC).
3. **The L1 re-root is unbounded.** `krsm.io/target` may name any tracked object, including a
   cluster-scoped owner spanning namespaces. The design says L1 is "bounded by a
   same-namespace constraint" (design:55) and also accepts "re-root L1 anywhere"
   (design:79), so it contradicts itself.
4. **"A request cannot mint its own authorization" overstates the oldObject rule.** An agent
   can add `krsm.io/target` in one UPDATE (admitted under L0) and use the wider scope in its
   next request.
5. **The re-key comment is false (`webhook/server.go:79`).** Reconfiguring a key makes the old
   key inert, and L0 can be *wider* than a contract or re-root the old key named.
6. **Step 6 is incomplete.**
   - There is no CHANGELOG entry.
   - ADR-0003 still says "resolves it from an informer".
   - `SECURITY.md` lacks the bearer-capability residual and #42, which the design claims are
     stated there.
   - The umbrella design's taxonomy, lifecycle, open questions, components and status are
     stale.
   - The plan still says "informer" in places, and every checkbox in the plan and test
     list is unticked.
7. **Cleanups.**
   - Stale comments: `state/provider.go` `GetByGVK`, the `server.go`
     `reasonScopeUnresolved`/`Handle` comments, and `internal/cluster/index.go`.
   - Dead code: the `cmd/krsm/main.go` `if contracts != nil` branch, whose typed-nil
     comment is wrong.
   - The comment claiming Compile rejects an empty `allow`, which it does not.
   - Late or missing flag validation: the key collision is only checked after informer
     sync; an empty key silently means the default; a `*` allowlist entry is taken literally.
   - A private-helper test (`allowlistApplies`) that an end-to-end test already covers.

## Approach
- **Finding 1.** `clauseNamespace` takes the contract's namespace and uses it as the
  default for resource/selector clauses, the same rule `rootNamespace` already applies.
  `namespace`/`ownership` dims still pass through literally. A contract with no namespace
  (offline YAML without `metadata.namespace`) keeps the loader's `default`, so offline
  behaviour and goldens are unchanged.
- **Finding 3.** After `parseTargetRef` resolves R, L1 checks two things, both
  `scope-unresolved` on failure:
  - **(a) Same namespace.** `R.Namespace == target.Namespace`, so a namespaced target can
    only re-root to a namespaced R in its own namespace, and a cluster-scoped target only
    to a cluster-scoped R.
  - **(b) Ancestor.** R is the target, or the target is reachable from R through
    `OwnedChildren`, by uid, with a visited set.

  This is the precise meaning of "re-root at an owner", L1's only documented use case.
  The alternatives were rejected:
  - *Same-namespace only, no ancestor check.* A non-ancestor re-root is already caught
    later, because the target escapes its own scope, but only as a Warn in audit mode. An
    early, named deny is clearer.
  - *A depth limit.* It is arbitrary.
- **Findings 2 and 4.** Documentation only. The residual is stated where operators read it
  (`SECURITY.md`) and where designers do (ADR-0003, design).
- **Finding 5.** Comment fix, plus one startup log line per reconfigured key.
- **Finding 7.** `runServe` validates the keys before any informer starts:
  - non-empty
  - pairwise distinct: target / scope / agent annotation
  - well-formed (`[prefix/]name`, k8s qualified-name rules)

  Allowlist entries must be non-empty and not `*`. Remove the no-op `if contracts != nil`.

## Risks & unknowns
- **The L1 bound could reject a legitimate re-root.** That happens if an owner chain passes
  through an untracked kind, because `OwnedChildren` only knows tracked objects. This is
  acceptable: it fails closed with a message naming the missing link, and the operator can
  track the kind.
- **Finding 1 could change offline semantics.** Mitigated: a contract without a namespace
  keeps `default`, and the goldens pin the behaviour.

## Definition of done
- A live contract's resource/selector clauses default to the contract's namespace.
- L1 accepts only the target or an in-namespace owner ancestor, and denies everything
  else as `scope-unresolved` in both modes.
- Serve rejects bad keys and allowlist entries before the informers start, and warns on a
  re-keyed channel.
- Findings 2 and 4 are stated in `SECURITY.md` and ADR-0003.
- Step 6 of the slice-6 plan is complete.
- `make check` is green, goldens 01–27 are unchanged, and the work is staged for the
  user to commit.
