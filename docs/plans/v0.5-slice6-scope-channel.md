# Plan: v0.5-slice6-scope-channel
Status: draft · Date: 2026-07-31 · Slug: `v0.5-slice6-scope-channel`

## Problem
Issue **#24** (slice 6 of the v0.5 milestone). The webhook today hardcodes **Level-0
derived scope**: `webhook/server.go` `Handle` calls `pred := scope.Derive(action.Target)`
directly (one call site, deliberately isolated in slice 5 for exactly this replacement).
ADR-0011 defines a **progressive scope channel** — L0 derived / L1 target-annotation /
L2 templates / L3 full contract — with an audit-first default (shipped), a
**cross-boundary allowlist** escape hatch, and **provenance reporting**. Slice 6 delivers
**L0 + L1 + L3** (L2 templates are v0.6), the allowlist, and provenance, by replacing that
single `scope.Derive` call with a `resolveScope` seam.

Coupled to this slice (because slice 7 ships the TaskContract as a `krsm.io/v1alpha1` CRD
and the webhook must read/compile those objects): **flip the TaskContract `apiVersion`
from `krsm.io/v1` to `krsm.io/v1alpha1`** in `scope.Compile` + tests + contract goldens.
Decisions locked with the user (2026-07-31): slice 6 next (canonical order); CRD
apiVersion `krsm.io/v1alpha1`.

## Goals / Non-goals
- **Goal:** a `resolveScope(req, target) → ([]closure.ScopeClause, provenance, error)`
  seam in `webhook/scope.go`, priority **L3 contract > L1 annotation > L0 derived**,
  replacing the single `scope.Derive` call in `Handle`.
- **Goal (L1):** `krsm.io/target: "<Kind>/<ns>/<name>"` on the request re-roots the
  ownership-tree derivation at that target; provenance `annotation`.
- **Goal (L3):** an agent references a `TaskContract` (annotation, key decided in Open Q1);
  KRSM resolves it from a **TaskContract lister** (a dedicated informer over the
  `krsm.io/v1alpha1` TaskContract GVR), maps the CR to `scope.TaskContract`, and
  `scope.Compile`s it; provenance `contract`.
- **Goal (fail-closed):** a request that **references a contract we cannot resolve**
  (CRD absent, name not found, or uncompilable) **fails closed** — the agent claimed a
  scope KRSM cannot verify (Open Q3).
- **Goal (allowlist):** a configurable cross-boundary allowlist (startup config, Open Q2)
  of namespaces + cluster-scoped kinds removes those refs from the **escaping** set for
  **derived (L0/L1) modes only**; a contract (L3) states its own scope and ignores it.
- **Goal (provenance):** the resolved provenance flows into the existing
  `decisionResponse` message (it already prints `pred.Provenance`).
- **Goal (apiVersion):** `scope.Compile` accepts `krsm.io/v1alpha1` (rejects `krsm.io/v1`);
  `scope_test.go` and every contract golden fixture updated in lockstep — **verdicts
  identical**, only the `apiVersion` literal changes.
- **Goal:** hermetic throughout (crafted requests + `closure.NewScanState`/fake listers);
  `make check` green (incl. archguard, `-race`, goldens 01–27 verdicts unchanged).
- **Non-goal:** **L2 templates** (`spec.template` expansion) — deferred to v0.6.
- **Non-goal:** the **TaskContract CRD manifest, cert/RBAC/webhook-config, Helm chart** —
  that is slice 7 (#25). This slice reads whatever CRD slice 7 will ship.
- **Non-goal:** **contract trust / issuer validation** (a compromised agent authoring its
  own permissive contract) — ADR-0003's deferred open question; threat-model, out of scope.
- **Non-goal:** any **new closure/scope dimension** — reuse the existing
  `ownership`/`namespace`/`selector`/`reference` dimensions and `scope.Compile`; the
  engine and `closure.Safe` do not change (ADR-0011: "the only new code is the
  synthesizer").
- **Non-goal:** live-cluster / kind e2e (#27) and the CRD's real installation (#25).

## Current state

  `closure.Safe(s.state, action, pred.Clauses)` → `mode.Apply` →
  `decisionResponse(dec, pred.Provenance)`. **One** scope call site.
- `scope/scope.go`: `Derive(target) ScopePredicate` (L0, `ProvenanceDerivedOwner`);
  `Compile(tc) (ScopePredicate, error)` (L3, `wantAPIVersion = "krsm.io/v1"`,
  `wantKind = "TaskContract"`); `Provenance` ∈ {`contract`, `derived:ownership-tree`};
  `ScopePredicate{Clauses, MaxSeverity, Provenance}`; `Mode.Apply` (audit downgrade).
  Stdlib-only (archguard).
- `internal/scenario/scenario.go:657` `parseTaskContract(raw []byte) (scope.TaskContract,
  error)` — the YAML→`TaskContract` mapper (unexported, CLI/golden path).
- `state.Provider`: informers over **closure-relevant** tracked GVRs only; it does **not**
  watch `TaskContract` — slice 6 adds a separate lister.
- Contract goldens under `closure/testdata/scenarios/*/` declare `apiVersion: krsm.io/v1`.
- `docs/design/v0.5-admission-webhook.md` §"Scope resolution (slice 6)" already sketches
  the `resolveScope` signature and the `Server{resolver, allowlist, taskContractLister}`
  fields — this plan realises that sketch.
- `cmd/krsm serve`: `--agent-annotation krsm.io/task` (agent **identity** matcher — a
  distinct concern from scope reference).

## Approach
Introduce `webhook/scope.go` with `resolveScope(req, target)`:
1. **L3** — if the request carries the scope-contract reference annotation (Open Q1),
   look the named `TaskContract` up in the **TaskContract lister**, map the CR
   (`unstructured`) → `scope.TaskContract`, `scope.Compile` → `(clauses, "contract")`.
   Any failure to resolve/compile a *referenced* contract → error (fail closed).
2. **L1** — else if `krsm.io/target` is present, parse `"<Kind>/<ns>/<name>"` →
   `scope.Derive(thatRef)` → `(clauses, "annotation")`; a malformed value → error.
3. **L0** — else `scope.Derive(target)` → `(clauses, "derived:ownership-tree")`.

`Handle` calls `resolveScope`; on error it fails closed (a new `invalid`/dedicated
reason). For L0/L1 the **allowlist** is applied to `dec.Escaping` before `mode.Apply`
(allowlisted namespaces/cluster-scoped kinds are not escapes); L3 skips it.

**TaskContract lister:** a dedicated dynamic informer over the `krsm.io/v1alpha1`
`taskcontracts` GVR, held by the `Server` behind a small `contractLister` interface
(hermetically fakeable). It **tolerates the CRD being absent** (zero-config audit
install): the lister is simply empty, and L3 only *fails closed* when a request actually
references a contract that cannot be found. The unstructured→`scope.TaskContract` mapper
reads the CR's `spec` (the same wire shape `parseTaskContract` accepts) — a dedicated
mapper in `webhook/` (not a reuse of the unexported scenario parser; the informer yields
`unstructured`, not YAML bytes).

**apiVersion flip** is step 1 (foundational, isolatable): change the `scope.Compile`
constant to `krsm.io/v1alpha1`, update `scope_test.go` and every contract golden's
`apiVersion` literal together; verdicts are byte-identical.

Alternatives weighed:
- **Allowlist in a CRD vs webhook startup config** → startup config (ADR-0011 says
  "configurable"; no second CRD; simpler for the zero-config story). (Open Q2.)
- **Export `internal/scenario.parseTaskContract` vs a dedicated webhook mapper** →
  dedicated mapper: the informer gives `unstructured` not YAML, and coupling the webhook
  to the scenario/YAML loader is the wrong dependency direction.
- **Track TaskContract in `state.Provider` vs a separate lister** → separate lister:
  TaskContracts are not closure objects; keep the closure index clean and the lister
  independently startable/absent-tolerant.
- **Referenced-but-unresolvable contract: fail closed vs fall back to derived** → fail
  closed (Open Q3): silently downgrading a claimed contract scope to the (possibly wider
  or narrower) derived one hides intent and can false-ALLOW.

## Steps (vertical slices)
1. [ ] **apiVersion `krsm.io/v1` → `krsm.io/v1alpha1`.** `scope.Compile` constant +
   `scope_test.go` + every contract golden fixture, in lockstep. Test: `Compile` accepts
   `v1alpha1`, rejects `v1`; goldens 01–27 verdicts unchanged. Demo: `make check`.
2. [ ] **`resolveScope` L0 + L1.** Extract the derived call into `webhook/scope.go`
   `resolveScope`; add `krsm.io/target` parsing → re-rooted `scope.Derive`; wire `Handle`
   to it. Tests: annotation re-roots the ownership tree (a verdict the request target
   alone could not express); malformed `krsm.io/target` fails closed; no annotation ⇒ L0
   unchanged (existing slice-5 tests stay green).
3. [ ] **Cross-boundary allowlist (L0/L1).** Startup config → allowlist; strip
   allowlisted namespaces / cluster-scoped kinds from `dec.Escaping` before `mode.Apply`;
   L3 ignores it. Tests: an allowlisted shared-namespace reference no longer escapes
   (audit: no warn; enforce: admitted); a non-allowlisted escape still Warns/Blocks.
4. [ ] **L3 contract.** `contractLister` seam + `unstructured → scope.TaskContract` mapper
   + `scope.Compile`; the scope-contract reference annotation (Open Q1); provenance
   `contract`; fail closed on referenced-but-unresolvable. Tests: a resolvable contract
   authorising the tree **Allows** an action that derived-enforce would Block; a
   referenced-but-missing/uncompilable contract fails closed; an *unreferenced* request is
   untouched (L0).
5. [ ] **serve wiring.** Start the TaskContract informer (tolerant of an absent CRD);
   flags for the allowlist + the scope-contract annotation key; `buildWebhookConfig` wires
   the resolver + lister + allowlist; hermetic serve-wiring tests (mirror
   `serve_wiring_test.go`).
6. [ ] **Docs + review record.** Update `docs/design/v0.5-slice6-scope-channel.md`
   (this pipeline's design), the umbrella design's slice-6 section, and CHANGELOG; note
   the CRD manifest + deployment are slice 7.

## Risks & unknowns
- **CR→`scope.TaskContract` fidelity:** the informer's `unstructured` `spec` must map to
  the same shape `parseTaskContract` produces from YAML; pin with a golden contract CR
  compiled to identical clauses.
- **Lister when the CRD is absent:** the webhook must start and serve L0/L1 with no
  TaskContract CRD installed; the informer registration must not hard-fail discovery
  (reuse the slice-1 C1-tolerant discovery posture).
- **apiVersion flip touching goldens:** ensure ONLY the `apiVersion` literal changes and
  every contract golden's expected verdict is byte-identical (parity/`make check`).
- **Annotation-key hygiene:** `krsm.io/task` is the **agent-identity** matcher key; the
  **scope** channel needs distinct keys (`krsm.io/target` for L1; Open Q1 for L3) so
  identity and scope never collide.
- **Contract trust (ADR-0003 open Q):** a compromised agent could author a permissive
  TaskContract and reference it. Out of scope here (threat-model), but the fail-closed
  resolution and the audit default limit blast radius; note it in the design.

## Definition of done
`resolveScope` selects L3 > L1 > L0 with the correct provenance reported in the verdict;
`krsm.io/target` re-roots the derivation; a cluster `TaskContract` (`krsm.io/v1alpha1`)
authorising the tree flips a would-Block derived verdict to **Allow**; a referenced-but-
unresolvable contract **fails closed**; the allowlist exempts configured shared
namespaces / cluster-scoped kinds in **L0/L1 only**; `apiVersion` is `krsm.io/v1alpha1`
across code + tests + goldens with **identical verdicts**; `make check` green (archguard,
`-race`, goldens 01–27); work staged for the user to commit (Claude never commits). No CRD
manifest, no deployment, no L2 templates, no live-cluster test.
